# 2-3. 완벽한 익스플로잇 계획 세우기

이제 우리는 리눅스 커널 해킹을 위해 필요한 핵심 개념과 명령어들을 모두 배웠습니다! 본격적인 공격에 앞서, 현재까지 배운 무기들을 다시 한번 정리해 봅시다.

- `prepare_kernel_cred()` : 새로운 신분증(권한, cred)을 만드는 함수.
- `init_task` : 리눅스 부팅 후 최초의 프로세스(root 권한으로 실행됨)의 정보.
- `commit_creds()` : 현재 프로세스의 신분증을 교체하는 함수.
- `swapgs` : 커널 영역과 사용자 영역의 데이터/스택 영역을 교체하는 특권 명령어.
- `iretq` : 인터럽트(예외) 처리를 마치고 원래의 사용자 영역으로 복귀할 때 사용하는 특권 명령어.

그럼 이제 이번 장에서 우리의 최종 목표인, **커널 영역을 익스플로잇 하여 root 권한을 탈취한 뒤, 다시 사용자 영역으로 안전하게 돌아오는 것**을 어떻게 달성할지 계획을 세워봅시다.

우리는 `syscall` 명령어를 통해 커널 영역으로 넘어왔고, `entry_SYSCALL_64`의 시작점에서 `swapgs`를 통해 커널 영역의 스택을 사용하도록 세팅되었습니다. 그렇다면 목표 달성까지 남은 작업들은 무엇일까요?

바로 아래의 작업들을 순서대로 하는 것입니다!

1. **권한 탈취** : 커널 내부의 취약점(버퍼 오버플로우 등)을 사용하여 `commit_creds(prepare_kernel_cred(&init_task))`를 강제로 실행합니다. 이제 프로세스는 root 권한을 갖습니다.
2. **스택 복귀** : `swapgs` 를 강제로 실행하여 커널 영역으로 맞춰진 스택 상태를 사용자 영역의 것으로 돌려놓습니다.
3. **안전하게 탈출** : 사용자 모드로 권한을 하락시키고, 사용자 영역의 코드로 실행 흐름을 복귀시킵니다.

1번 과정은 1장에서 해보았던 것처럼 커널 스택 버퍼 오버플로우 등 소프트웨어 취약점 익스플로잇 기법을 사용해 진행할 수 있습니다.

<strong>가장 중요하고 까다로운 과정은 바로 복귀 과정인 2, 3번 과정입니다.</strong> 모든 작업을 마치고 사용자 영역으로 돌아가려면 어떤 명령어를 써야 할까요?

우리는 2-2장에서 시스템 호출이 정상적으로 끝날 때는 보통 `sysret` 명령어를 쓴다고 배웠습니다. 하지만 `sysret`은 커널이 정상적인 상태일 때 실행되며, 돌아갈 주소를 RCX 같은 레지스터에서 꺼내옵니다. 익스플로잇 상황에서 해커가 이 레지스터 값들까지 원하는 대로 맞추기는 까다롭습니다.

무엇보다 우리가 공격을 진행하는 시점에는 **커널의 스택 및 힙 등 메모리 영역이 이미 심각하게 훼손(오염)된 상태입니다!** 커널에게 정상적인 복귀 동작(`sysret`)을 기대했다가는 곧바로 운영체제가 멈출(커널 패닉) 확률이 높습니다.

이럴 때 사용할 수 있는 복귀 주문이 바로 `iretq` 명령어 입니다!

`iretq`는 명령어는 사용자 영역으로 복귀할 때 **현재 커널 스택의 최상단(RSP)에 놓인 5개의 값을 차례대로 읽어서 복귀할 주소와 권한 상태를 결정합니다.**

아래 사진은 `iretq`가 실행될 때, 커널이 스택에서 순서대로 꺼내는 5개의 값을 표시한 것입니다.

![iretq](../images/Chapter_2/image-7.png)

따라서, 해커는 커널 스택에 \[RIP, CS, RFLAGS, RSP, SS\] 이 5개의 값을 순서대로 기록하고, `iretq` 명령어를 실행하여 커널이 스택에서 이 값들을 꺼내게 합니다. 그러면 커널이 이 값들을 읽어 우리가 원하는 상태로, 사용자 영역으로 돌아갈 수 있게 해줍니다!

자, 이론적인 권한 상승 및 무사 귀환 계획이 완벽하게 세워졌습니다. 이제 이것을 실제 환경에서 실험해 볼 것인데... 그 전에 마지막으로 꼭 짚고 넘어갈 개념이 하나 남았습니다.

## iretq가 스택에서 꺼내는 5개의 값은 정확히 무엇일까요?

앞서 2-2장에서 `iretq`는 하드웨어 인터럽트나 심각한 예외(Exception)를 처리하고 복귀할 때 쓰는 무거운 명령어라 설명한 것을 기억하시나요?

프로그램 실행 중 `int 3`(디버그 중단점)나 `SIGSEGV`(잘못된 메모리 접근), 혹은 키보드 입력 같은 하드웨어 요청이 발생하면 CPU에게 <b>인터럽트(Interrupt)</b>가 전송됩니다.

인터럽트를 받은 CPU는 **즉시 현재 하던 일을 잠시 중단하고 커널 모드로 진입하여 인터럽트를 먼저 해결합니다.** 실행하는 작업은 인터럽트 종류마다 다르며, 시스템 호출 테이블처럼 인터럽트 발생 시 실행할 함수들을 모아 놓은 테이블이 운영체제에 정의되어 있습니다. 인터럽트가 종료되면 다시 원래 하던 일을 마저 계속합니다.

그렇다면 운영체제는 어떻게 '인터럽트가 발생한 직후의 프로세스 상태' 를 기억하는 걸까요?

프로세스 실행 중 인터럽트가 발생하면, CPU는 **하드웨어적으로 즉시 커널 모드로 바꾼 다음 먼저 현재 사용자 프로세스의 핵심 레지스터 5개를 커널 스택에 백업해 놓습니다.** 스택에 들어가는 순서는 \[SS -> RSP -> RFLAGS -> CS -> RIP\] 이며, 이렇게 스택에 들어간 5개 레지스터의 집합을 <b>트랩 프레임(Trap Frame)</b> 이라 합니다.

> 트랩(Trap)이라 부르는 이유는, 소프트웨어 실행 중 발생한 인터럽트를 트랩이라 부르기 때문입니다.

인터럽트 처리 과정을 마치고 마지막에 `iretq`를 실행하면, 스택에 저장된 트랩 프레임을 역순(RIP -> CS -> RFLAGS -> RSP -> SS)으로 뽑아서(Pop), 완벽하게 원래 실행 흐름으로 되돌아올 수 있습니다.

**이제 해커의 시선으로 이 `iretq` 명령어를 살펴봅시다.**

우리는 `iretq` 명령어를 마음대로 실행할 수 있고, 동시에 커널 스택에 쌓일 스택 프레임 데이터도 마음대로 설정할 수 있습니다! 그렇다면 우리가 사용할 트랩 프레임에는 순서대로 어떤 값을 써야 할까요?

|순서|레지스터|넣어야 할 값|설명|
|---|---|---|-----|
|1|RIP|원하는 값|**가장 중요한 값**으로, 복귀 직후 실행할 코드의 주소입니다. 일반적으로 셸(`/bin/sh`)을 획득하는 함수로 설정해 놓습니다.|
|2|CS|0x33|코드 세그먼트입니다. 끝자리가 3인 것은 Ring 3(유저 영역)으로 돌아가겠다는 뜻입니다. (x86_64 리눅스 시스템 고정값입니다.)|
|3|RFLAGS|0x202|CPU의 상태 플래그입니다. 0x202는 필수적인 하드웨어 인터럽트를 허용하는 아주 안정적인 기본 상태값입니다.|
|4|RSP|원하는 값|복귀 후 유저 영역에서 사용할 스택 주소입니다. 주로 익스플로잇 시작 전 미리 백업해둔 원래의 사용자 RSP 값이나, 스택 영역에 큰 배열을 하나 만들고 해당 영역을 스택으로 사용합니다.|
|5|SS|0x2B|스택 세그먼트입니다. 유저 영역의 스택 권한 상태를 나타냅니다. (x86_64 리눅스 시스템 고정값입니다.)|

얼핏 보면 복잡해 보이지만, 해커 입장에서는 CS(0x33), RFLAGS(0x202), SS(0x2B)는 리눅스 환경에서 쓰는 매직 넘버를 고정값으로 쓰면 됩니다.

우리가 진짜로 신경써야 할 것은 **복귀 주소(RIP)와 돌아가서 사용할 스택(RSP) 뿐입니다!**

스택에 이 5개의 값을 순서대로 기록하고 `iretq`를 실행하면, 커널은 이 가짜 트랩 프레임을 읽고 우리가 원하는 위치의 실행 흐름으로 복귀하게 됩니다. 이 상태로 셸을 획득하는 프로세스를 실행하면 즉시 root 권한의 셸을 획득하게 됩니다.

이제 진짜로 여러분의 손에 Root 권한을 거머쥘 시간입니다! 실습으로 넘어가 봅시다!

### 잠깐! 매직 넘버들의 상세 작동 원리가 궁금해요.

다음은 RFLAGS, CS, SS 레지스터에 설정하는 기본값들의 원리에 대한 상세 설명입니다.

- RFLAGS = 0x202
    * 이 레지스터는 CPU의 현재 상태를 저장하고 제어하는 64비트 레지스터이며, 각 비트마다 0 또는 1로 상태를 표시합니다.(상세 비트 맵은 [Wikipedia FLAGS register](https://en.wikipedia.org/wiki/FLAGS_register)을 참조하세요.)
    * 익스플로잇 관점에서는 대부분의 상태 비트가 중요하지 않지만, 두 가지 비트는 반드시 챙겨야 합니다.
        * Bit 1 (0x002) : x86-64 하드웨어 표준 규격상 **항상 1로 고정**되어 있는 예약 비트입니다.
        * Bit 9 (0x200) : <b>IF(Interrupt Enable Flag)</b> 비트입니다. 사용자 모드로 복귀한 뒤 키보드, 타이머 등 하드웨어 인터럽트를 정상적으로 수신하기 위해 **반드시 1로 켜두어야 합니다.** (0으로 설정할 경우 인터럽트가 제대로 작동하지 않아 시스템이 즉시 마비됩니다.)
    * 따라서 `0x200 + 0x002 = 0x202`를 기본값으로 사용합니다.
- CS(Code Segment) = 0x33, SS(Stack Segment) = 0x2B
    * 두 레지스터는 16비트 크기의 세그먼트 셀렉터(Segment Selector) 레지스터로, 주소가 아닌 다음과 같은 비트 구조를 가집니다.
        * \[1:0\] 비트 : **[1:0] 비트:** 권한 레벨(RPL). `00`은 Ring 0(커널 영역), `11`은 Ring 3(사용자 영역)입니다.
        * \[2\] 비트 : `0`일 경우 GDT(Global Descriptor Table)를 참조합니다.
        * \[15:3\] : GDT 테이블 상에서 몇 번째 항목(Index)인지를 나타냅니다.
    * 64비트 리눅스 커널의 GDT 규칙에 따라 다음과 같이 계산됩니다.
        * **CS (`0x33`) :** GDT 6번 엔트리(64비트 유저 코드) + Ring 3 권한 $\rightarrow$ `(6 << 3) | 3` = `0x33`
        * **SS (`0x2B`):** GDT 5번 엔트리(유저 스택/데이터) + Ring 3 권한 $\rightarrow$ `(5 << 3) | 3` = `0x2B`
    * 64비트 환경에서 메모리 주소 지정 용도로는 쓰이지 않지만, CPU가 **"유저 권한(Ring 3) 및 64비트 모드로 안전하게 복귀하는가?"**를 하드웨어적으로 검증할 때 참조되므로 리눅스 기본 상수를 그대로 설정해 줍니다.
