# 1-2. 커널 모듈의 취약점

앞서 우리는 Linux 커널 모듈을 만들고 적재하여 운영체제에 새로운 기능을 추가하는 방법을 배웠습니다.

하지만 커널 모듈 역시 사람이 C언어로 작성한 프로그램입니다. 만약 개발자의 실수로 코드에 취약점이 남아있다면, 해커들은 이 틈을 파고들어 커널의 막강한 권한을 탈취할 수 있습니다.

다음은 우리가 앞서 만든 커널 모듈의 핵심 코드 조각입니다. **혹시 해커들이 사용할 수 있는 치명적인 취약점이 눈에 보이시나요?**

```c
static ssize_t dev_write(struct file* filep, const char __user* buffer, size_t len, loff_t* offset) {
    char k_buffer[64]; // 버퍼 크기

    printk(KERN_INFO "[VULN] Received %zu bytes from user\n", len);
    /* _copy_from_user 는 버퍼에 사용자 입력을 입력 길이만큼 그대로 복사합니다! */
    if (_copy_from_user(k_buffer, buffer, len)) {
        return -EFAULT;
    }

    return len;
}
```

정답은 '버퍼 오버플로(Buffer overflow)' 입니다!

dev_write 함수가 선언한 k_buffer의 크기는 64바이트입니다. 하지만 해커가 len에 200 등 큰 수를 넣고 매우 긴 입력을 주면?

코드를 살펴보면 사용자 입력 길이를 검증하는 부분이 없으므로, k_buffer에 buf 데이터가 그대로 복사가 됩니다. 이 경우 사용자 영역에서의 버퍼 오버플로가 그러하듯 **커널 메모리의 중요한 값들이 마구잡이로 변조됩니다!**

이때 함수가 끝난 뒤 돌아갈 위치를 정해둔 반환 주소(Return Address)까지 덮어씌워진다면? 운영체제가 엉뚱한 곳의 코드를 실행하려 하게 되어 커널 패닉(Kernel Panic. 운영체제가 멈추게 됩니다.)이 발생하거나, 실행 흐름이 해커의 손에 넘어가게 됩니다.

### 💡 잠깐! \_copy\_from\_user 는 copy\_from\_user와 무엇이 다른가요?

두 함수 모두 C언어의 memcpy와 비슷한 역할을 하는 커널의 데이터 복사 함수들입니다.

- `copy_from_user` (일반 함수): 사용자가 모듈을 개발할 때 사용을 권장하는 표준 함수입니다. **함수 내부적으로 버퍼 크기를 초과하는 데이터가 들어오면 복사를 차단하는 안전장치가 내장**되어 있습니다.

- `_copy_from_user` (언더바가 붙은 함수): 커널 내부에서 아주 빠르게 메모리를 복사할 때 쓰는 함수로, **데이터 복사 안전장치가 없습니다.**

이 문제에서는 실습을 위해 일부러 안전장치가 없는 함수를 사용하여 취약한 환경을 구축한 것입니다!

다음 절에서는 이제 이 버퍼 오버플로 취약점을 사용하여, 실제로 커널을 무너뜨리고 플래그를 획득해 보겠습니다. **여러분의 첫 번째 해킹 시간이 다가왔습니다!**
